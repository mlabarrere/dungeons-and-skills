# Agent portability

This is an agent-portable skill distribution. The **skills** in `skills/` and the **rules base**
in `data/` + `engine/` hold the behavior; the host-specific files are **thin adapters** that make
that behavior easy to load in a given agent. Adapters never diverge from the source — they are
generated from the `dnd-builder` section of `AGENTS.md` by `scripts/build-adapters.mjs`, and
`scripts/check-rule-copies.mjs` fails CI if any copy drifts.

## The skills follow the open Agent Skills format

`skills/` targets the [Agent Skills specification](https://agentskills.io/specification) — the
open format now implemented by dozens of agent products. `scripts/check-skills-spec.mjs` enforces
it in CI: spec-only frontmatter, `description` within 1024 characters, and **no path that escapes
a skill folder**. That last rule is what makes a skill directory independently copyable — each one
carries its own `scripts/dnd.mjs` (the engine door) and, when it cites them, its own `references/` copies of the rule
texts it cites, both generated and drift-checked.

## Status definitions

- **Certified beta host** — the skill trigger and deterministic CLI path have a recorded release
  smoke test for that host.
- **Agent Skills compatible** — the host implements the open format, but its complete user
  experience is not part of the release gate.
- **Instruction-only** — the host loads an always-on rule or project knowledge. It applies the
  grounding rule and reads `data/` by hand without deterministic engine execution.

## Supported hosts

Any client implementing the Agent Skills format reads `skills/` directly — the list below names
the ones with documented support, not an exhaustive set. See the
[client showcase](https://agentskills.io/clients).

| Host/path | Files | Status |
|-----------|-------|--------|
| Node CLI from checkout | `engine/`, `data/` | CI-certified engine |
| Claude Code | `.claude/skills/`, `commands/` | Certified beta host |
| OpenAI Codex | `.agents/skills/`, `AGENTS.md` | Certified beta host |
| Cursor | `skills/` (fallback: `.cursor/rules/dnd-builder.mdc`) | Certified beta host |
| VS Code / GitHub Copilot | `skills/` (fallback: `.github/copilot-instructions.md`) | Agent Skills compatible |
| Kiro | `skills/` (fallback: `.kiro/steering/dnd-builder.md`) | Agent Skills compatible |
| Gemini CLI, OpenCode, Goose, Amp, Factory, OpenHands | `skills/` | Agent Skills compatible |
| Claude Projects / ChatGPT Projects / Custom GPTs | `project-mode/INSTRUCTIONS.md` + `project-mode/knowledge/` | Instruction-only |
| Windsurf | `.windsurf/rules/dnd-builder.md` | Instruction-only |
| Cline | `.clinerules/dnd-builder.md` | Instruction-only |
| Any other agent | `AGENTS.md` or manually loaded `skills/` | Instruction-only unless locally verified |

The rule-file adapters are kept for hosts that predate skills support, and as a fallback where a
user prefers an always-on rule to an on-demand skill. They are still generated and drift-checked.
No npm-registry package or marketplace listing is published yet.

## Adapter rule

Keep adapters thin. When a host supports skills, point it at `skills/`. When a host only supports
project instructions, keep its copied rule text aligned with the `dnd-builder` section of
`AGENTS.md` (the generator + `check-rule-copies` enforce this).

## Portable behavior

- `skills/dnd-build/SKILL.md` — guided level-1 character creation
- `skills/dnd-check/SKILL.md` — audit/validate an existing sheet
- `skills/dnd-lookup/SKILL.md` — catalog-only rules lookup
- `skills/dnd-optimize/SKILL.md` — optimal build under constraints, engine-scored
- `skills/dnd-help/SKILL.md` — family overview + grounding explainer
- `AGENTS.md` — compact always-on instruction set for agents without skill support
- `rules/grounding.md` — the load-bearing rule embedded verbatim everywhere

Each skill folder also carries, all generated by `scripts/build-adapters.mjs`:

- `scripts/dnd.mjs` — resolves and runs the engine from any working directory; exits 2 with
  install instructions when the rules bundle is absent
- `references/` — the `rules/` texts that skill cites, so it needs nothing outside its folder.
  Only skills that cite them get a copy: `dnd-help` has no `references/`, because it explains the
  toolkit rather than applying the rules
- `evals/` — output-quality cases (`evals.json`) and triggering queries (`trigger_queries.json`)

## Adding a host

Add the target file to `scripts/build-adapters.mjs`, run it, and add the file to the adapter
list in `scripts/check-rule-copies.mjs` so drift is caught. See [CONTRIBUTING.md](CONTRIBUTING.md).
